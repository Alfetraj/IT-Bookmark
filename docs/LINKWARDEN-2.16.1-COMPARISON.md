# Linkwarden 2.16.1 vs. IT-Bookmark Comparison Report

This document outlines the comparative audit between the local `linkwarden-2.16.1` source and the current `IT-Bookmark` implementation, identifying gaps and required actions for transformation.

| Area | Linkwarden 2.16.1 | IT Bookmark | Gap | Action |
|------|-------------------|-------------|-----|--------|
| **Authentication** | NextAuth (Credentials + OAuth), robust session handling via Prisma `Account`/`User`. | Custom Express JWT via `public.users` table. | Missing OAuth, API Key integration, granular sessions. | Retain JWT but expand to support `AccessToken` (API Keys) and robust session validation. |
| **Users** | Stores rich preferences (archive settings, AI method, dashboard sections, theme). | Basic `(email, password, name)`. | Missing user preferences and AI configuration. | Add preference columns to `public.users` (theme, archive settings, AI toggle). |
| **Bookmarks (Links)** | `Link` model with `preview`, `image`, `pdf`, `readable`, `monolith`, `textContent`, `aiTagged`. | `bookmarks` table with `screenshot_path`, `pdf_path`, `readability_content`, `is_favorite`, `read_later`. | Linkwarden relies on Collections/Tags for "Read Later". IT-Bookmark has built-in booleans. Missing `monolith` and `aiTagged`. | Retain `is_favorite` and `read_later`. Add `monolith_path`, `text_content` (for Meilisearch), and `ai_tagged` flags. |
| **Collections** | Supports nesting (`parentId`), icons, colors, public sharing, and collaboration (`UsersAndCollections`). | Supports nesting (`parent_id`), colors, `is_public`. | Missing sharing/collaboration roles (Owner, Editor, Viewer) and icons. | Create `collection_members` table. Add `icon` column. Implement permission logic in backend. |
| **Tags** | Tracks `aiGenerated`, allows overriding archive settings per tag. | Basic name, color, slug. | Missing AI flags and per-tag archive settings. | Add `ai_generated` and archive override columns to `tags`. |
| **Archiving Workflow** | BullMQ/PostgreSQL-based worker using Playwright, capturing Screenshot, PDF, Readability, and Monolith. | In-memory `setInterval` worker using Playwright for Screenshot, PDF, Readability. | IT-Bookmark worker lacks robust retry, locking, and concurrency. | Upgrade worker to use PostgreSQL-backed job queue (e.g., PgBoss or custom lock table) with robust retry logic. Add Monolith format. |
| **Storage** | Pluggable `filesystem` package (Local, S3, Azure, etc.). | Hardcoded Supabase Storage bucket. | No abstract `StorageProvider` interface. | Create `StorageService` interface wrapping Supabase Storage, architected for future S3 integration. |
| **Search & Indexing** | Meilisearch integration via background sync (`linkIndexing.ts`). | Simple SQL `ILIKE` queries. | No full-text indexing for extracted content. | Implement full-text search. Either deploy Meilisearch or utilize PostgreSQL full-text search (`tsvector`) for simplicity. |
| **RSS Integration** | Dedicated `RssSubscription` model and background polling worker. | None. | Completely missing. | Create `rss_subscriptions` table and polling worker to auto-ingest feeds into collections. |
| **AI Tagging** | Uses Vercel AI SDK (OpenAI, Anthropic, Ollama) on extracted text to suggest/assign tags. | None. | Completely missing. | Add AI Provider abstraction to optionally run after archive extraction to generate tags. |
| **Annotations / Highlights** | `Highlight` model (text offset, color, comment) for marking up reader view. | `notes` column on bookmark. | Missing robust text highlighting logic. | Create `highlights` table referencing bookmark ID and text offsets. |
| **Sharing & Collaboration** | Granular collection permissions via `UsersAndCollections`. | Public collections only (`is_public`). | Missing secure member invites and roles. | Implement `collection_members` table and API endpoints for inviting users. |
| **Import / Export** | Parses Netscape HTML, handles large batches. | Basic Netscape HTML parsing with Cheerio. | IT-Bookmark lacks bulk UI progress and background processing for massive imports. | Upgrade import service to queue background jobs for archiving imported links. Add Export service. |
| **API & API Keys** | `AccessToken` model, documented REST routes for programmatic access. | No API keys. Express routes exist but not tokenized for external use. | Missing API Key generation and management. | Create `api_keys` table. Add middleware to accept `Bearer {api_key}` alongside JWTs. |
| **Dashboard** | Dynamic via `DashboardSection` (stats, recent, pinned, specific collections). | Static UI with placeholders. | Missing real aggregation endpoints. | Create `/api/dashboard/stats` and populate real data. |
| **Security / Isolation** | Protects Playwright against SSRF. Content isolation. | Playwright worker has no strict SSRF protections. | High risk of SSRF via bookmark URLs. | Implement URL sanitization (block private IPs, localhost) before Playwright navigation. |

## Conclusion
IT-Bookmark has a solid foundational Clean Architecture using Express and Supabase, but it lacks the robust background processing (concurrency/locking), collaboration features, full-text search, and advanced AI/RSS integrations found in Linkwarden. The migration path will focus on **extending the database schema**, **upgrading the worker architecture** using PostgreSQL locks, and **implementing the missing domain features** one phase at a time.
